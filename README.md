# Speedora — MVP على Cloudflare Workers + D1

نسخة أولية لمنصة مهام ونقاط تجريبية، بواجهة عربية وWorker واحد يخدم الموقع وواجهات API.

## الملفات
- `worker.js`: الواجهة والـ API في Worker واحد.
- `wrangler.toml`: ربط قاعدة D1 الحالية.
- `schema.sql`: الجداول والفهارس.
- `README.md`: تعليمات التشغيل.

## النشر من الهاتف عبر GitHub وCloudflare
1. أنشئ مستودع GitHub باسم `speedora`.
2. ارفع الملفات الثلاثة في جذر المستودع: `worker.js`, `wrangler.toml`, `schema.sql`.
3. من Cloudflare افتح **Workers & Pages → Create → Worker**. هذا مشروع **Worker** وليس Cloudflare Pages.
4. الأسهل: افتح Worker ثم **Edit code** والصق محتوى `worker.js`، أو استخدم إعداد Git deployment إذا كان متاحاً في حسابك. تأكد أن نقطة الدخول `worker.js`.
5. من Worker → Settings → Variables and Secrets أضف متغيراً نصياً باسم `ADMIN_EMAIL` واجعل قيمته بريدك الذي ستنشئ به أول حساب أدمن.
6. اربط D1 binding باسم `DB` واختر قاعدة `speedora-db` ذات المعرّف الموجود في `wrangler.toml`. لا تنشئ قاعدة جديدة إذا كانت هذه هي القاعدة المقصودة.
7. من D1 → `speedora-db` → Console نفّذ محتوى `schema.sql` مرة واحدة.
8. انشر Worker وافتح رابط `workers.dev`.

## إنشاء أول أدمن
- أضف `ADMIN_EMAIL` قبل إنشاء الحساب.
- سجّل حساباً باستخدام نفس البريد. سيُمنح دور `admin` تلقائياً.
- لا تترك `ADMIN_EMAIL` مضبوطاً على بريد عام أو غير مملوك لك.

## اختبار سريع
- افتح `/api/health` ويجب أن يظهر `{"ok":true,...}`.
- أنشئ حساباً من `/signup`.
- سجّل الدخول من `/login`.
- افتح `/dashboard` ثم `/tasks` و`/wallet`.
- بحساب المعلن، انشر مهمة بعد إضافة نقاط إلى رصيده من خلال إجراء إداري موثوق/بيانات اختبار فقط. لا توجد واجهة شحن رصيد في هذه النسخة.
- بحساب عامل آخر، أرسل رابط إثبات للمهمة.
- افتح `/admin` بحساب الأدمن لمراجعة الإثبات واعتماده.

## حدود مهمة قبل الإطلاق العام
هذه نسخة MVP تجريبية وليست نظاماً مالياً جاهزاً للإطلاق:
- النقاط داخلية وتجريبية فقط؛ لا يوجد سحب أموال أو دفع أو تكامل بوابة دفع.
- لا يوجد نظام شحن رصيد للمعلنين؛ لا تضف أرصدة يدوياً لمستخدمين حقيقيين.
- إثبات المهمة حالياً رابط URL فقط، وليس رفع ملف.
- أضف Cloudflare Turnstile وRate Limiting فعلياً قبل فتح التسجيل للعامة. كما يلزم اختبار أمان مستقل واختبارات ضغط ومراجعة تدفق النقاط.
- استخدم نطاق HTTPS. Cookies مضبوطة `Secure` و`HttpOnly` و`SameSite=Strict`.
- يجب أن تكون كل حركة رصيد موثقة في `wallet_ledger`. لا تعدّل رصيد المستخدم مباشرة من الواجهة أو من API عام.

## ملاحظة تقنية
هذا المشروع يستخدم Cloudflare Workers وD1 مباشرة. لا تنشره كـ Cloudflare Pages Static Site؛ صفحات Pages لا تشغّل ملف Worker بهذه الطريقة.
